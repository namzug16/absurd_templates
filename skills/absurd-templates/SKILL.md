# Absurd Templates (abs)

`abs` turns a directory of `.html` templates into **one self-contained Dart
file**: each template becomes a typed function returning a `Fragment`, and
`fragment.toHtml()` renders it. There is no runtime package and no template
parsing at run time.

## Find your way around

Read `abs.yaml` in the project root first. It says where everything is:

```yaml
input: components                # .html templates, scanned recursively
output: lib/generated/html.dart  # the generated Dart file
class: Html                      # entry class; Components when absent
```

The generated file is output, not source. Never edit it: the next `abs` run
overwrites every change. Change the `.html` template, then regenerate.

## The edit loop

1. Edit or create the `.html` file under the `input` directory.
2. Run `abs check path/to/template.html`. It writes nothing and reports
   syntax errors and Dart type errors with file, line, column and a caret
   under the problem, in well under a second. Pass several files to check
   them together; pass none to check every template.
3. Fix what it reports and run it again until it prints `abs check: ... OK`.
   It reports only the first syntax error of each template, so a clean
   result needs a re-run after every fix.
4. Run `abs` to regenerate the output file.
5. Update the Dart code that calls the component if its props changed, and
   run the project's usual `dart analyze` and tests.

If `abs` is not on the PATH, try `dart run absurd_templates:abs` (same
arguments); if neither works, ask the user how they run it.

`abs check` exits with 1 on errors, so it fits scripts and CI. Its messages
usually say what to do next; read the whole message before changing code.

## Template syntax

```html
<x-props
  title="String"
  users="List<({String name, bool active})>"
  footer="Fragment?"
></x-props>

<section>
  <h1>{{ title }}</h1>
  <ul>
    <x-for in="users" as="user" indexed="1" index-as="number">
      <x-if case="user.active">
        <li class="user">{{ number }}. {{ user.name }}</li>
      </x-if>
    </x-for>
  </ul>
  {{ footer }}
</section>
```

That is the whole language: four constructs.

- **`<x-props>`** declares the component's parameters: attribute name =
  parameter name, attribute value = Dart type. It must be the first thing in
  the file and be closed right away with `</x-props>`. Nullable types
  (`String?`, `Fragment?`) become optional named parameters; all others are
  `required`. A template without `<x-props>` takes no parameters.
- **`{{ value }}`** writes a value. Text is HTML-escaped (`& < > " '`), a
  `Fragment` is inserted as HTML, `null` writes nothing, and an `Iterable`
  (such as `List<Fragment>`) writes each item in order. It works in text and
  inside quoted attributes: `<a class="{{ kind }}">`.
- **`<x-for in="list" as="item">`** repeats its children for each item of any
  `Iterable`. For a counter, add both `indexed="1"` (the start value, any
  integer) and `index-as="number"` (the variable name).
- **`<x-if case="flag">`** renders its children when the value is `true`. It
  must be a `bool`; there is no `else`.

Values in `{{ }}`, `in` and `case` can only be a variable in scope (a prop or
an enclosing loop variable) followed by fields or getters: `title`,
`user.name`, `pair.$1`, `items.isEmpty`. Nothing else is allowed: no
operators, method calls, `!`, `??`, string interpolation or filters. This is
deliberate: templates stay trivially readable and every value is type-checked.
Compute anything else in Dart and pass it in as a prop.

Other rules:

- A directive tag alone on its line is removed together with that line, so
  indent freely; the output has no blank lines where tags were.
- `<!-- comments -->` are copied to the output and directives inside them
  are ignored.
- Escaping makes text safe in HTML and in quoted attributes, but not as a
  URL: `href="{{ url }}"` with `javascript:...` still runs. Validate URLs for
  `href`, `src` and `action` in Dart before passing them in.

## Working without missing features

| You want | Do this |
|---|---|
| `else` | A second `<x-if>` on the opposite flag: `items.isEmpty` and `items.isNotEmpty`, or pass two `bool` props computed in Dart. |
| `!flag`, `a && b`, `count > 0` | Compute a `bool` in Dart (`showBanner: !user.dismissed`) and pass it as a prop. |
| Formatting (dates, money, uppercase) | Format in Dart and pass a `String`. |
| One component inside another | Give the outer one a `Fragment` prop (`content="Fragment"`) and compose in Dart. |
| A list of components | A `List<Fragment>` prop, written with `{{ cards }}`. |
| Optional section | A nullable prop (`footer="Fragment?"`) written with `{{ footer }}`; nothing renders when it is `null`. |
| Raw, unescaped HTML | Only through a `Fragment` built by another component; plain strings are always escaped. |

## Calling components from Dart

File paths become Dart names: directories become namespaces and file names
become camelCase methods on the class from `abs.yaml`.

| Template | Dart |
|---|---|
| `components/header.html` | `Html.header()` |
| `components/pages/user-page.html` | `Html.pages.userPage(...)` |
| `components/layout/primary.html` | `Html.layout.primary(...)` |

```dart
import 'generated/html.dart'; // the `output` path from abs.yaml

final html = Html.layout.primary(
  title: 'Users',
  content: Html.pages.users(
    title: 'Users',
    users: [(name: 'Ada', active: true)],
    footer: Html.footer(),
  ),
).toHtml();
```

File and directory names must turn into valid, distinct Dart identifiers:
`404.html`, `switch.html`, or both `user-page.html` and `user_page.html` in
one directory are errors. Rename the file when `abs` reports a conflict.

## When something goes wrong

- **An error points at the generated file** (from `dart analyze` in the
  project): every generated statement ends in a comment such as
  `// components/pages/users.html:12:16`. Go to that template line instead.
- **"... is not declared"**: the name is not a prop or loop variable in
  scope (the message lists the ones that are); fix the spelling or add it
  to `<x-props>`.
- **"only accepts a variable or its fields"**: an expression was used; move
  the logic into Dart and pass the result as a prop.
- **Type errors** (`The getter 'nmae' isn't defined`, `Conditions must have a
  static type of 'bool'`): fix the field name or the prop type.
- **"was not generated by abs, so abs will not overwrite it"**: `output`
  points at a hand-written file. Point it elsewhere instead of deleting the
  file, unless the user confirms.
- **No `abs.yaml`**: run `abs init` to create a commented one, then adjust
  `input` and `output`.
